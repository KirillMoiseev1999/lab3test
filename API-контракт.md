# Контракт API сервиса учёта подписок

Базовый путь — `/api/v1`. Локальный API работает по HTTPS и принимает JSON в UTF-8. Защищённые операции требуют заголовок `Authorization: Bearer <token>`. Владелец определяется по токену. Для отсутствующего и чужого объекта возвращается одинаковый ответ 404.

## Маршруты

| Метод и путь после /api/v1 | Операция | Статусы HTTP |
|---|---|---|
| POST /auth/register | Регистрация по email и паролю | 201, 400, 409 |
| POST /auth/login | Вход и выдача токена на 30 минут | 200, 400, 401, 429 |
| POST /auth/logout | Отзыв текущего токена | 204, 401 |
| POST /auth/password-reset/request | Запрос восстановления | 202, 400 |
| POST /auth/password-reset/confirm | Смена пароля по одноразовому токену | 204, 400 |
| GET /subscriptions | Список с фильтрацией и пагинацией | 200, 400, 401 |
| POST /subscriptions | Создание подписки | 201, 400, 401 |
| GET /subscriptions/{id} | Получение подписки | 200, 401, 404 |
| PUT /subscriptions/{id} | Замена редактируемых полей | 200, 400, 401, 404 |
| DELETE /subscriptions/{id} | Архивация с сохранением истории | 204, 401, 404 |
| POST /subscriptions/{id}/payments | Запись фактического платежа | 201, 400, 401, 404, 409 |
| GET /payments | История платежей | 200, 400, 401, 404 |
| GET /analytics/expenses | Фактические расходы | 200, 400, 401 |
| GET /analytics/forecast | Прогноз платежей | 200, 400, 401 |
| GET /calendar | Календарь плановых платежей | 200, 400, 401 |
| GET /health/ready | Готовность приложения и базы данных | 200, 503 |

## Подписки

Пример тела запроса `POST /api/v1/subscriptions`.

```json
{
  "name": "Музыкальный сервис",
  "category": "Музыка",
  "price": "399.00",
  "currency": "RUB",
  "frequency": "monthly",
  "nextPaymentDate": "2026-11-30",
  "status": "active"
}
```

- Название содержит 1–100 символов, категория — 1–50. Цена положительна и не превышает 999999999.99. Допустимые валюты — RUB, USD и EUR. Денежные значения передаются строками с точностью до двух знаков и обрабатываются как `decimal`.
- Периодичность — `monthly` или `yearly`. Статус — `active`, `paused` или `archived`. Ответ содержит поля запроса, `id` и `billingDay`.
- Для списка доступны `status`, `category`, `page` и `pageSize`. Нумерация страниц начинается с 1. Размер страницы по умолчанию 20, допустимый диапазон 1–100. Сортировка по дате следующего платежа, затем по ID. Пустая страница возвращает 200 и `items: []`.
- Повторная архивация возвращает 204. История и возможность записывать фактические платежи сохраняются.

## Платежи и аналитика

Для `POST /api/v1/subscriptions/{id}/payments` передаётся заголовок `Idempotency-Key`.

```json
{"amount":"399.00","currency":"RUB","paidOn":"2026-10-31"}
```

- Сумма положительна и не превышает 999999999.99. Валюта совпадает с валютой подписки, а дата платежа не позже текущей даты UTC. Ответ дополняет поля запроса значениями `id` и `subscriptionId`.
- Повтор с тем же ключом и нормализованными данными в течение 24 часов возвращает прежний ID и 201. Ключ привязан к пользователю и операции. Если данные отличаются, возвращается 409. Ключ и платёж сохраняются атомарно.
- Даты передаются в формате `YYYY-MM-DD`, временные метки — в UTC. История, расходы, прогноз и календарь требуют `from` и `to`, причём `from < to`. Интервал включает `from` и исключает `to`. Прогноз и календарь ограничены 366 днями. История дополнительно принимает `subscriptionId`, `page` и `pageSize`.
- Расходы группируются по валюте (`byCurrency`) и по текущей категории и валюте (`byCategory`). Суммы разных валют возвращаются отдельно.
- Прогноз и календарь включают только активные подписки. Фактический платёж не изменяет плановую дату автоматически. При коротком месяце используется последний день месяца, а исходный расчётный день сохраняется. Для годовой подписки сохраняется и расчётный месяц.

Проверка ФТ-10. Для подписки с расчётным днём 31 и началом 31 января 2026 года календарь за `[2026-02-01, 2026-04-01)` должен вернуть 28 февраля и 31 марта.

## Доступ и ошибки

Пароль содержит 12–128 символов. После пяти неудачных попыток входа за 15 минут дальнейшие попытки в этом окне возвращают 429. Запрос восстановления с допустимым адресом возвращает 202 независимо от наличия аккаунта. Одноразовый токен действует 15 минут и отправляется через email-адаптер.

Общий ответ об ошибке содержит `code`, `message`, `requestId` и при необходимости словарь `errors` с ошибками полей. Недоступность базы данных возвращает 503, непредвиденная внутренняя ошибка — 500. Стек вызовов клиенту не передаётся.
